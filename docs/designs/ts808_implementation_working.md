## Milestone ordering and completion evidence

1. **Freeze inputs before equations:** source/extraction, component map, device laws and exact parameters, numerical/data contracts and finite matrix. Resolve contradictions before coding either model.
2. **Qualify components and assembly:** build the core; pass finite-difference, KCL, history and Schur-equivalence tests before relying on full-pedal output.
3. **Qualify the reference path:** use required LTspice settings, verify float64 binary storage and reader compatibility, and establish reconstruction/reference uncertainty with real and analytic fixtures.
4. **Run the offline acceptance matrix:** report every required case and each agreed gate; distinguish DC/solver failure, model error, temporal error and unqualified reference/export. No complete pass while required metrics are undefined.
5. **Promote only after evidence:** repeat at finer fixed rates, archive identified artifacts and document baseline scope. Later runtime optimization repeats the same accuracy suite before TS9/modification work.

## Verification plan construction

The final design must specify reproducible configure/build/test and analysis commands for the selected versions/platforms; those commands have not been executed. Required checks are meaningful device-derivative tests, assembly/state invariants, reference precision/reconstruction qualification, analytic measurement tests and the complete paired LTspice/C++ matrix. Coverage is defined by required physical/numerical regimes and failure paths, not an invented percentage alone.

The selected stop-on-failure policy is tested deliberately with invalid states/singular systems and exhausted work budgets. A test that only reproduces the production formula without independent perturbations/invariants is insufficient. User ABX and later CPU/latency/aliasing checks need their separately specified protocols before those claims can be made.
